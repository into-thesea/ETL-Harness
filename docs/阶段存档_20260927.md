### 1.1 审批中断持久化（checkpointer 默认落 SQLite）

**修的缺陷**：`HarnessService` 默认 `MemorySaver` —— 审批中断是进程内状态，**服务一重启待审批任务就蒸发**，已判 ✅ 的"工具级审批"只在单进程生命周期内成立。计划 §9.3 原把"断点恢复验证"评为低优先，依据是"②会顺带解决"；②已落地但该前提被证伪，评级重算为最高。

**关键实现事实（都不是推测，是实测）**：
- 服务用 `ainvoke`/`aget_state` 驱动图，**同步 `SqliteSaver` 的异步方法直接 `NotImplementedError`** → 必须用 `AsyncSqliteSaver`；
- `AsyncSqliteSaver.__init__` 里就 `asyncio.get_running_loop()` → **异步 saver 绑定事件循环，只能在运行中的循环里构造** → 装配推迟到首个异步入口（`HarnessService._ensure_ready`）；
- 建表由 saver 首次使用时自动完成（库文档明确要求**不要**手工调 `setup()`）；
- serde 必须显式登记图状态里的类型，否则每个类型一条警告、且库声明未来版本会**阻断**；登记不全时类型会被**直接阻断**（状态退化成 dict、图在下游炸）——所以按模块穷举 `harness.models`，而不是手写几个名字。

配置：`CHECKPOINT_BACKEND=sqlite`（默认）/`memory`、`CHECKPOINT_SQLITE_PATH`。未知取值显式 `ValueError`，**不静默回退**。

### 1.2 数据质量校验节点 + QA 质检子 Agent

- `QualityGate` 增 `data_quality_checker`：体检画像缺失率/重复率越线 → `GateDecision.HUMAN` → 复用既有 interrupt 审批通道（**与 1.1 正好合上：这个暂停现在能跨重启存活**）。
- 阈值语义是实测调出来的：**只拦 (阈值, 100%) 之间的部分缺失**，整列全空视为"待删列"交给 cleaner。详见 `docs/遇到的问题.md` #23。
- Critic（质量门裁判）**默认开启**：此前 `use_critic` 在生产恒为 `False`，这条能力一直是死的。提示词补三类分析逻辑缺陷：幸存者偏差 / 辛普森悖论 / 数据泄露。
- 新增 `qa` 子 Agent（只审不改，工具限 `data_inspector`/`eda`/`sql_query`），并同步进 `DEFAULT_AGENT_ROLES`（注册表里有名字但缺角色描述 → 规划器渲染成裸名字，等于看不见）。
- **波动异常未实现**：仓库没有任何时序指标，凭空定义等于编造标准。如实标注，待真实数据后立项。

### 1.3 中文 PII 规则层，并把它真正接上

- 规则层抽成模块级纯函数 `mask_text`/`mask_value`；身份证按 GB 11643 校验位、银行卡按 Luhn、手机号按号段，前后加 `(?<!\d)/(?!\d)` 边界（不从更长数字串里切出手机号/卡号）。
- 修掉三处"有模块≠生效"：中间件**从未被注册**；`after_tool` 只脱敏文本、**不脱敏 artifacts**（真实行数据在 artifacts 里）；**不实现 `before_llm`**（发给模型的提示词没脱敏）。
- 出站覆盖四处：推理节点（原有）+ **规划器** + **质量门裁判** + **顶层汇总** —— 规划提示词里是用户原始目标。
- **SQL/代码类工具入参不脱敏**（`PII_SKIP_TOOLS`）：那是查询条件/字面量，脱敏会把查询改坏、结果与原始数据不一致，属正确性要求。

### 1.4 C5 真实 MySQL / PostgreSQL（含一处安全缺陷修复）

- `infra/docker-compose.yml` 增 `postgres:16` / `mysql:8`，端口用 **55432 / 53306**（避开本机其他项目占用的 5432/3306），初始化脚本建**只读账号**；`tests/conftest.py` 增 `needs_db` 闸门 + `--require-db`。
- **修掉一个静默失效的安全措施**：PG 的"连接级只读"在 psycopg3 下**是假的** —— `SET` 放在 `connect` 事件里执行，会随连接归还池时的 rollback 一起回滚，写操作实际能成功。改用连接参数（PG `options=-c default_transaction_read_only=on`；MySQL `init_command=SET SESSION TRANSACTION READ ONLY`）。**是用"管理员账号 + 写入必须失败"这条用例逼出来的** ——只读账号那条路上数据库在权限层就先拒了，永远测不到这一层。详见 `docs/遇到的问题.md` #21。
- 修正文档里的驱动名错误（`psycopg2` → `psycopg`），并补"不需要数据库在线"的驱动层用例；补 `requirements.txt` 缺失的 `SQLAlchemy/psycopg/PyMySQL`。
- **只读有证据**：白名单拒绝写语句（PG+MySQL）；数据库层拒绝直连写（只读账号 PG+MySQL）；连接级只读拒绝有写权限账号（PG+MySQL）；PG 的 `SELECT ... INTO`（白名单漏网形状）被数据库层拦下。

### 1.5 行列级权限（SQL 改写强制注入 WHERE）

- 新 `harness/permissions/row_column.py`：用 **sqlglot** 解析后改写（注入 WHERE / 列白名单校验），在 `sql_query` 里**注入 LIMIT 之前**落点（LIMIT 之后再插 WHERE 是语法错）。
- **fail closed**：多语句、UNION 等非单 SELECT、解析失败、`SELECT *`（无法做列级校验）、行过滤归属不唯一（跨层多次引用/自连接）一律**拒绝**，不勉强改写。
- 把此前**从未接进装配**的 PDP 接上（配置驱动、**默认放行**以保持既有行为），行列规则由 `PERMISSION_*` 控制、未配置时完全不介入；规则表的默认态度是**未命中即拒绝**（白名单语义），可用 `PERMISSION_UNMATCHED_ROLE=allow` 改。

**⚠️ 初版被独立审查打穿三个洞，已修并补 12 条回归用例**（详见 `docs/遇到的问题.md` #26）：
① 列白名单只查最外层投影 → 套一层子查询把禁列改名即可整列泄漏（实测返回全部手机号）；
② 行过滤注入到最外层 SELECT → 受管表在子查询里时全量读出；
③ sqlglot 的 FROM 参数名是 `from_`，写成 `from` 静默取到 None → 所有行级规则查询被拒。
另修 PG 的 dict 命名参数 `:name` 被渲染成 `%(name)s`（仅"PG + 命中规则"组合下失败）。
**教训：权限特性必须用"绕过它的写法"去测，否则绿灯给的是虚假保证。**
