## 第一部分 · 项目基本盘（必背）

### 30 秒电梯陈述

"我做了一个 Agent Harness——用 LangGraph 做编排骨架，围绕模型手写了工具调度、权限、审批、记忆、沙箱、审计这层管控运行时；并以企业级数据分析为首个内置领域，跑通从数据接入到报告产出的端到端链路。"

### 灵魂三问（各 2-3 句）

- **是什么 / 不是什么**：是框架 + 参考领域实例；不是某个 to C 产品，也不是重造 LangChain。
- **解决什么痛点**：直接用 LangGraph 要自己拼管控；长任务上下文爆炸、越权、不可信代码、出问题无法追溯。
- **和现成框架的区别**：对 AutoGen/Pi，本项目是"管控能力全含 + 服务化"，Pi 是极简内核。

Python · LangGraph（编排骨架）· FastAPI（服务化）· Redis（短期记忆/任务）· Milvus（长期向量）· Kafka（审计/追踪）· MinIO（VFS 对象存储）· OpenSandbox（代码沙箱）· SQLAlchemy（多数据源）· Pydantic（数据契约/配置）。

## 第二部分 · 架构与主链路（能空手画图）

### 四层架构

```
接入层        FastAPI：任务提交 / SSE 流式 / 状态查询 / 审批（Bearer 鉴权）
编排层        LangGraph：顶层 Plan-and-Execute，子任务内 ReAct（think → action → final）
管控运行时    Tool Broker · 中间件 · PDP / 行列权限 · 审批 · 上下文管理 · Skills · 沙箱
状态与记忆    VFS · Redis 短期 · Milvus 长期 · 工作记忆 · Checkpoint
基础设施      Docker Compose：Redis / Milvus / Kafka / MinIO（+ 可选 MySQL/PG）
```

### 任务生命周期

`POST /tasks` 拿 thread_id → planner 拆子任务 → 派给子 Agent（ScopedBroker 限权）→ ReAct 循环 think/action → 高危操作 interrupt 等人审批 → 大结果落 VFS、上下文压缩 → 报告/图表产出。

### 同步内核 + 异步外壳

- **同步内核**：tool_broker、nodes、graph、pdp、middleware、vfs、memory、tools/*——普通函数和类。
- **异步外壳**：FastAPI 路由（async def）、后台 asyncio.Task、asyncio.Lock、异步 checkpointer、MCP 会话、SSE。
- **理由**：编排逻辑用同步，简单、好测、好调试；只在等待网络/数据库/SSE 的 I/O 边界用异步拿并发。

## 第三部分 · 分层踩坑问答（真实问题：思路 → 答案）

### 接入 / 鉴权层

**Q1：两层权限会不会被一个请求字段绕过？**
- 思路：先看"权限判定依赖的身份从哪来"，再看身份能否被客户端改写。
- 答：早期 role 是请求体客户端自填、默认 admin，PDP 和行列权限都按它判，等于"能自称 admin"。修复：角色只能来自 `Authorization: Bearer` 对应令牌（AUTH_TOKENS），请求体 role 字段删除，未配令牌启动即失败。判据：身份若来自请求里客户端可写字段，那层权限不成立。

**Q2：prompt 里写"需人工审批"算实现审批了吗？**
- 思路：区分"提示/记录"与"真正的执行闸门"。
- 答：不算。早期标记只被读两处（给模型的提示词、给审计的记录），执行路径无闸门。最终用 LangGraph interrupt：执行到点真正暂停、决策后续跑，与 checkpointer 配套、状态落盘重启可续。

### 编排层

**Q3：为什么把数据库连接管理器放进 state，任务一启动就崩？**
- 思路：讲 checkpointer 序列化机制，区分运行时设施与纯数据。
- 答：checkpointer（含 MemorySaver）用 msgpack 序列化整个 state；Engine、连接池、锁、socket 不可序列化，第一个检查点就崩。修复：DataSourceManager 走节点构造函数注入，只有纯数据进 state。

**Q4：上下文压缩为什么偶发导致工具调用被 400？**
- 思路：识别"工具调用消息与结果必须成对"，看压缩是否切在配对中间。
- 答：压缩把消息当"角色+文本"，折叠边界可能切在发起调用与结果之间，逐条裁剪会丢发起方、留结果。修复：窗口边界约束——保留窗口对齐到合法角色、永不切配对中间，挤出的旧消息并入摘要。

**Q5：切原生 Function Calling 后某步为何被 422？**
- 思路：对比框架内部消息形态与服务商契约。
- 答：框架内部 type 是内部值、参数是 dict；服务商要求固定 type、参数是 JSON 字符串并带 tool_call_id。修复：组装请求前统一归一化并带配对 id。

### 管控运行时

**Q6：模块单测全过，为什么主链路不生效？**
- 思路：反复出现的"有模块≠生效"，逐个查装配点。
- 答：撞过三次——ContextManager 没接两个时机；PII 中间件没注册（且只脱敏工具文本、不脱敏 prompt）；PDP 没传进 Broker。修复：两处接线、逐层透传，中间件同时挂图和 Broker，各留"确实接上"的用例。

**Q7：沙箱踩过哪些坑？**
- 思路：按"装→连→执行→判定"顺序讲根因。
- 答：①某版本服务端漏打协议模块启动即崩——锁版本 0.2.3、装独立 venv；②旧服务端只收字符串命令——按服务端改；③镜像无可写目录——运行时用文件接口创建；④超时被杀无完成事件被误判——改量测提交到返回的实际耗时。

**Q8：MCP 为何"参数说明空、失败当成功"？**
- 思路：先查字段命名，再查协议语义。
- 答：客户端字段下划线风格、代码按另一种取，取不到走兜底（静默错误）；MCP 把正常返回一律当成功。修复：两种命名都取；失败走异常通道。

**Q9：模型为何反复对不存在的文件调工具、撞步数上限？**
- 思路：查路径口径，以及报错是否给自纠信息。
- 答：上游给虚拟路径、下游只认宿主路径，虚拟路径在 Windows 被判绝对路径直接报错；报错不列可用文件，模型只能猜。修复：虚拟→宿主路径映射，报错列出可用文件。实测任务从 failed/55% 变 finished/100%。

### 数据 / 数据源 / 行列权限层

**Q10：声明了 PG 只读，为何管理员账号一测就能建表？**
- 思路：安全措施要绕过其他防线单独验证。
- 答：SET 放在 connect 事件里，psycopg3 下隐式开事务，连接归还时 rollback 把设置回滚。修复：用连接参数 `connect_args={"options":"-c default_transaction_read_only=on"}`（MySQL 用 init_command）。

**Q11：行列权限初版全绿，怎么被打穿三个洞？**
- 思路：用绕过写法（子查询/CTE/别名/跨层）测。
- 答：①列白名单只校验最外层投影，子查询改名即绕过，过滤/排序里的禁列也不查；②行过滤注入最外层而非拥有受管表的 SELECT；③sqlglot 30.x FROM 参数是 `from_`，写错静默取 None。修复：整树扫描列、行过滤注入唯一拥有该表的 SELECT（归属不唯一直接拒绝），新增 12 条绕过回归，修掉"文本含数字"的假绿断言。

**Q12：ResourceWarning 连接泄漏根因？**
- 思路：查谁创建/替换 Engine、有没有关闭。
- 答：同名数据源重复注册时 pop 出旧 Engine 直接丢弃、没 dispose，连接池连接失去引用直到 GC 才告警。修复：替换前先 dispose；`pytest -W error::ResourceWarning` 零警告。

**Q13："连不上要干净失败"的用例为何拖到几分钟？**
- 思路：区分立即拒绝与挂起后超时，查连接超时配置。
- 答：Docker 端口代理对无人监听端口挂住约 4 秒才拒，psycopg 默认无连接超时。修复：真实连接带 connect_timeout，必失败场景用保留端口+瞬时拒绝地址。

### 上下文 / 记忆 / 配置层

**Q14：改 .env 不生效还不报错？**
- 思路：检查配置加载是否传播到嵌套模型。
- 答：pydantic-settings 不把 env_file 向下传给嵌套子模型，子模型只从进程环境读，配置体系成摆设。修复：实例化前显式把 env 载入进程环境（锚定绝对路径）。

**Q15：上下文沉淀阈值何时变成死代码？**
- 思路：用计数器观测真实触发，不靠推断。
- 答：内置工具自身已"长结果落盘、只回摘要"，真实调用回内核文本都在阈值内，沉淀一次没触发；阈值只在工具真返回长文本（代码 stdout、未来自定义工具）时有价值。配套加沉淀/压缩计数。

### 决策 / 文档 / 质量层

**Q16：降级和"本地缓冲、恢复补发"是一回事吗？**
- 思路：区分容错降级（可能丢数据）与可靠投递（语义不变、只延迟）。
- 答：不是。Kafka 审计不能丢，改为本地 spool 落盘、恢复后补发；MinIO/本地文件是二选一的合法部署形态，不叫降级。

**Q17：质量红线为何第一步就拦住自己的示例？**
- 思路：核对阈值语义与真实数据，不硬凑。
- 答：待删列整列全空（100%）被"缺失率>30%"拦住；应只拦部分缺失、全空列交 cleaner 并标 all_null。"波动异常"当时无时序指标、无法实现，如实留空待立项。

## 第五部分 · 异步与 FastAPI 专题

### 异步分布

- `server/service.py`：接口 async def；asyncio.Task 维护后台任务、asyncio.Lock 每任务锁、异步初始化 checkpointer。
- `checkpoint.py`：async build/close checkpointer；异步 SQLite saver 需在事件循环里建。
- `mcp_adapter.py`：async 会话生命周期、await initialize。
- `tests/`：asyncio.run(scenario()) 包裹、await 接口、asyncio.sleep 轮询。

### 高频问答

1. **用异步了吗，为何不全用？** → 同步内核 + 异步外壳；I/O 边界用 async 拿并发，编排逻辑同步更可控。
2. **FastAPI 怎么跑耗时 Agent？** → 不在请求里阻塞，收到后用后台任务异步执行、立即返回 thread_id，进度走 SSE/轮询。
3. **SSE 怎么实现？** → EventSourceResponse 持续推事件；EventSource 不能设头，故该路由额外接受 ?token=（仅此路由，避免鉴权后门）。
4. **asyncio.Lock 解决什么？** → 同一任务并发访问（轮询 + 提交审批）串行化状态变更，防竞态。

### 掌握要求

- 会手写：FastAPI async 路由 + Pydantic 请求/返回、SSE 生成器骨架、asyncio.run 异步测试。
- 能讲清：同步/异步边界与理由、后台任务 + Lock。
- 看懂即可：异步 saver、MCP 异步会话内部。

## 第九部分 · 五条元规律

1. **不报错的错最贵**：配置没读到、字段名取不到、失败当成功，都"看着正常"。
2. **有模块 ≠ 生效**：要接线、要透传、要验证默认路径走到（撞过 3 次）。
3. **安全用"能绕过它的输入"测**：否则验证的是别的防线。
4. **长任务才发作的，短测试测不出**：压缩切配对、路径口径、审批缺失。
5. **含句柄/锁的对象不进 state**：走构造注入，state 只放可序列化纯数据。

> 每个 bug 用 STAR 讲"现象→定位→根因→改法"，最后落到其中一条元规律，体现可迁移的工程判断力。
