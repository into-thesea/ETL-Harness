# 企业级数据分析Agent实施规划文档（基于Harness Engineering架构）

## 一、 总体架构设计规划

核心思路：将Harness的核心理念（任务规划、虚拟文件系统、子Agent委派、Skills、记忆、沙箱）深度结合数据分析领域特性。相比风控策略Agent，数据分析Agent的核心在于“代码执行的安全性与灵活性”、“大数据量下的上下文管理”以及“业务口径的统一与合规”。

### 1. 工具层（Tool Layer）规划
工具层是Agent的“手脚”，需要提供执行具体动作的能力。数据分析Agent极度依赖代码执行，因此工具设计需极其谨慎。
*   **数据接入与探查工具**：数据库查询工具（MySQL、PostgreSQL、ClickHouse、Hive等，支持分页、超时控制、强制Limit防OOM）；文件读取工具（CSV、Excel、Parquet、JSON，对接S3/OSS）；元数据获取工具（表结构、字段注释、数据量级、数据血缘）；API调用工具（企业内部业务系统、第三方SaaS数据API）。
*   **数据处理与执行工具（核心沙箱）**：Python执行器（Pandas/Polars/NumPy，用于复杂数据清洗和特征工程）；SQL执行器（将计算下推至数据库）；R执行器（满足特定统计场景）。
    *   *安全机制*：所有代码执行必须运行在隔离的沙箱环境中（如OpenSandBox或Docker），限制网络访问和本地文件系统挂载，只允许读取特定的数据挂载目录。
*   **分析与建模工具**：统计检验工具（T检验、卡方检验等）；机器学习工具（Scikit-Learn、XGBoost、Prophet的封装）；归因分析工具（维度下钻、贡献度计算）。
*   **可视化与报告产出工具**：图表生成工具（Matplotlib、Seaborn、Plotly、Pyecharts的代码生成与执行）；文档产出工具（python-pptx生成PPT、reportlab生成PDF、Jinja2+Markdown生成HTML）；BI工具集成（Tableau、PowerBI、Superset API对接）。
*   **企业协同与通知工具**：邮件发送、企业微信/钉钉/Slack消息推送、工单系统创建（如Jira）。

### 2. Skill层（技能系统）规划
Skill层是Agent的“专业知识”，主要解决“如何正确使用工具”。按照Harness的渐进式披露原则，Skill应包含SOP、Prompt、SQL模板、领域文档和Python脚本。
*   **数据清洗Skills**：数据探查SOP（缺失率、唯一值、异常值、分布）；缺失值处理Skill（均值/中位数/众数填充、插值、剔除）；异常值处理Skill（Z-score、IQR、分位数截断/盖帽法）；数据标准化Skill（Z-Score、Min-Max）；口径统一Skill（结合长期记忆，将业务黑话转换为标准SQL逻辑）。
*   **数据分析Skills**：描述性统计Skill（均值、方差、同环比、多维交叉表）；归因分析Skill（漏斗分析、杜邦分析）；时间序列Skill（趋势、季节性、异常波动检测）；A/B实验分析Skill（假设检验、置信区间、显著性判定）。
*   **报告与图表Skills**：图表选择SOP（根据数据特点选择最佳图表，防止乱画图）；报告排版SOP（标准企业报告结构：摘要 -> 核心指标 -> 归因 -> 结论与建议）；PPT生成Skill（自动填充企业标准PPT模板）。
*   **自我进化机制**：根据历史任务复盘，将成功的分析路径、纠正过的SQL错误、优秀的可视化代码沉淀为新Skill。

### 3. Agent编排与上下文管理规划
将复杂的数据分析需求拆解为DAG（有向无环图）。
*   **主Agent（主控调度）**：接收需求并拆解为（数据获取 -> 清洗 -> 探索性分析 -> 深度建模 -> 可视化 -> 报告生成）；维护任务状态（pending, in_progress, completed, failed），遇到失败自动回滚或重试。
*   **专职子Agent（减少上下文污染）**：
    *   数据接入Agent：负责与数据库/文件打交道，只返回Schema和采样数据。
    *   数据清洗Agent：执行清洗流水线，输出清洗后的文件路径。
    *   分析建模Agent：独立上下文，执行统计/机器学习，只返回结构化结论。
    *   可视化Agent：生成图表代码并执行，返回图片路径。
    *   报告撰写Agent：收集结论和图片，生成最终报告。
    *   QA/质检Agent：独立审查分析逻辑（幸存者偏差、辛普森悖论、数据泄露）。
*   **虚拟文件系统（VFS）**：目录规划 `/workspace/raw`、`/workspace/cleaned`、`/workspace/scripts`、`/workspace/charts`、`/reports/final`。**关键点**：大工具结果绝不进入模型上下文，只写入VFS，上下文中只保留路径、形状、字段列表和摘要。

### 4. 企业级扩展规划
*   **权限与数据安全**：行列级权限控制（RBAC，强制注入`WHERE`条件）；PII/敏感数据脱敏（自动识别并脱敏手机号、身份证等）；审批机制（Human-in-the-Loop，高风险操作挂起等待审批）。
*   **全生命周期记忆管理**：短期记忆（Redis存对话历史、任务断点、临时数据）；长期记忆（Milvus等存业务术语字典、优秀报告、用户偏好，支持跨会话恢复）。
*   **链路追踪与可观测性**：对请求、规划、SQL、代码执行、Token消耗等埋点；通过Kafka将日志发送到Langfuse/Arize等平台；记录AI生成的Python代码以便审计和复现。
*   **缓存与性能优化**：基于SQL指纹的Redis缓存；大模型调用失败重试、降级策略。
*   **数据质量与口径治理**：引入数据质量校验节点（缺失率>30%或波动异常则暂停）；对接企业数据字典/指标平台，确保计算口径一致。

## 二、 业界成熟能力与自研方向梳理

### 1. 可直接复用的成熟基础设施（拿来主义，通过中间件接入）
*   **代码执行与安全沙箱**：E2B、Jupyter Kernel Gateway、Docker/Firecracker微虚拟机方案非常成熟。沙箱内预装Pandas/Sklearn/Matplotlib，沙箱外挂载VFS，限制网络请求。
*   **全生命周期记忆管理**：Redis做短期记忆，向量数据库（Milvus/Qdrant）做长期经验沉淀。LangChain Memory、Mem0、Zep等框架已封装好“提取-写入-检索”流程。
*   **可观测性与链路追踪**：LangFuse、Arize Phoenix、LangSmith等产品完善，支持OpenTelemetry标准，能记录调用、工具、SQL、Token和报错堆栈。
*   **权限管控与数据脱敏（部分成熟）**：传统RBAC/ABAC系统（Apache Ranger、Open Policy Agent）成熟；LLM驱动的PII检测有现成API（Presidio、云厂商NLP服务）。
*   **Human-in-the-Loop（审批与干预）**：LangGraph、Dify、Coze等编排框架原生支持“中断”和“审批节点”。
*   **缓存与降级**：语义缓存（GPTCache）、基于SQL指纹的Redis缓存、大模型API降级路由在网关层面非常普遍。

### 2. 需重点定制开发的核心能力（尚未完全成熟）
*   **业务口径的自动对齐**：如何让Agent准确理解“活跃用户”在企业内部不同部门的不同定义（需强绑定企业数据字典/指标平台）。
*   **数据质量的智能拦截**：Agent自动发现数据分布异常并停止分析，而不是一本正经地胡说八道（需引入Great Expectations等数据质量工具并配合LLM判断）。
*   **复杂长任务的自适应编排**：遇到SQL报错、内存OOM时，能像人类数据分析师一样自动修正代码或切换策略（目前大部分Agent只能重试，缺乏深层反思能力）。

## 三、 分阶段实施路线建议

*   **MVP阶段**：先实现基础工具（SQL、Python执行）和安全沙箱，使用单一Agent完成“读取数据 -> 简单清洗 -> 生成图表”的闭环。
*   **进阶阶段**：引入子Agent委派和虚拟文件系统，解决长上下文和复杂任务的Token消耗问题；引入Redis/Milvus管理记忆。
*   **企业级阶段**：接入企业权限系统、脱敏中间件、审批流，完善链路追踪，构建自我进化的Skill体系。

**最终产品形态愿景**：具备企业上下文感知、代码执行能力、自我纠错机制和安全合规边界的“虚拟高级数据分析师”。可根据场景演化为：对话式分析助手（ChatBI）、数据分析Copilot、自动化报告机器人（定时Workflow）以及企业级Agent编排平台（PaaS）。
