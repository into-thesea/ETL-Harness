# 简历项目经历：ETL-Harness 工业级数据分析 Agent Harness

> 用法：简历空间有限时用"简历正文（推荐版）"；网申/详细面经可用"详细素材版"。
> 技术栈标签与面试亮点附在文末。

---

## 项目名称

**ETL-Harness —— 工业级数据分析 Agent Harness（智能体管控框架）**

**一句话定位**：基于 LangGraph 编排与自研 Harness 管控层构建的企业级数据分析智能体框架，将工具调用、权限、记忆、文件、安全与可观测性等"大模型之外的工程能力"沉淀为可复用底座，注册数据分析工具即可得到端到端的数据分析 Agent。

**技术栈**：Python · LangGraph · OpenAI Function Calling · MCP（FastMCP）· FastAPI · Redis · Milvus · Kafka · MinIO · Docker · Pydantic · pandas/matplotlib · tenacity

---

## 简历正文（推荐版，6 条）

- **自研 ToolBroker 统一工具调度层**：以"工具说明书（JSON Schema）+ 处理器"注册机制解耦工具定义与调用协议，内置参数校验、滑动窗口限流、异常兜底与调用审计；新增工具只需声明 Schema 与处理函数，**同一套工具零改动同时支持 ReAct、原生 Function Calling、MCP 三种调用方式**。
- **实现 ReAct 与原生 Function Calling 双模式工具调用**：基于 LangGraph 编排 think→action→observation 状态循环，ReAct 模式以文本/JSON 协议保证模型无关，Function Calling 模式对接 OpenAI 兼容 `tools` 接口获取结构化 tool_calls 并支持多工具并行；两种模式在 Broker 层归一化，可配置切换并对比效果。
- **接入 MCP（Model Context Protocol）工具生态**：实现 MCP 适配器，作为 Client 自动发现并接入外部 MCP Server 的远程工具、包装为本地工具，作为 Server 通过 FastMCP 将内置工具暴露给第三方 MCP 客户端，实现跨进程、跨语言工具的可插拔接入。
- **构建多层安全管控体系**：PDP 策略决策点实现"精确→通配→默认拒绝"三级 RBAC 权限判定；可插拔中间件在模型/工具/文件节点注入缓存、重试、PII 检测等 Hook；高风险代码通过 Docker 安全沙箱隔离执行（网络/进程/文件系统隔离 + 资源与超时限制）。
- **实现全生命周期记忆与上下文工程**：工作记忆 + Redis 短期记忆 + Milvus 长期向量记忆支持跨会话经验检索；自研虚拟文件系统（VFS）统一管理工作区/报告并做版本留痕；上下文管理器将大结果沉淀为文件、Prompt 仅保留摘要与链接，显著降低长任务 Token 消耗。
- **落地数据分析工具链与服务化**：实现数据体检、清洗、探索性统计分析、NL2SQL 安全查询、自动图表选型、沙箱代码执行六类工具，形成"体检→清洗→分析→可视化→自定义深挖"闭环；基于 FastAPI 提供同步与 SSE 流式接口，并以 Kafka 全链路埋点实现可观测、以 Checkpointer 支持断点恢复。

## 详细素材版（8 条，网申/面经备用）

- 设计并实现 ToolBroker 统一工具调度层，以 ToolDef（JSON Schema 说明书）+ ToolHandler（处理函数）注册机制解耦工具定义、实现与调用协议，内置 JSON Schema 参数校验、按工具维度的滑动窗口限流、异常统一兜底、调用审计与 `(成功否, 观察文本, 结构化产物)` 统一返回契约；工具与 ReAct/Function Calling/MCP 三种调用方式彻底解耦。
- 基于 LangGraph 的 StateGraph 编排 ReAct 推理循环（think/action/final 节点 + 条件边 + Checkpointer），并同时支持 OpenAI 兼容的原生 Function Calling：解析结构化 tool_calls、回传 `role="tool"` 消息、支持单次多工具并行调用；提供 `tool_mode` 开关在两种模式间切换，模型决策最终都归一化到 `broker.invoke(name, args)`。
- 实现 MCP 适配器双向打通：Client 方向通过 MCP 协议 `tools/list` 发现远程工具并将其包装为符合统一签名的本地处理器注册进 Broker，对上层模型透明；Server 方向基于 FastMCP 暴露内置工具，供 Claude Desktop、Cursor 等 MCP 客户端复用。
- 构建 PDP 策略决策点，按"精确 (角色,工具) → 角色通配 → 默认策略"三级匹配实现 RBAC，默认 deny 遵循最小权限原则；权限不足返回结构化观察而非抛异常，支持智能体自主调整。
- 设计可插拔中间件机制，在 before/after LLM、tool、file 及任务状态变更等节点注入 Hook，统一实现缓存、重试、PII 脱敏、权限校验等横切能力，支持运行时注册与移除。
- 实现三层记忆（工作记忆 / Redis 短期对话与任务状态 / Milvus 长期向量经验）与跨会话检索；自研 VFS 虚拟文件系统抽象 /workspace、/reports、/logs 等目录，支持读写编辑搜索与 MinIO/本地双后端、文件版本留痕与回滚；ContextManager 把大结果沉淀到文件、Prompt 仅注入摘要与文件链接，降低长链路 Token 占用。
- 建设可观测与韧性：基于 trace_id/span_id 的全链路埋点经 Kafka 上送（本地 JSON Lines 回退），审计日志对工具入参做 SHA256 脱敏；实现任务规划拆解与状态追踪、子 Agent 委派（独立上下文、仅回传结构化结论）、LangGraph Checkpointer 断点恢复与 tenacity 重试。
- 落地六类数据分析工具（数据体检、清洗、EDA 统计分析、NL2SQL 只读查询、自动图表选型、沙箱代码执行）形成完整分析闭环；基于 FastAPI + SSE 提供同步/流式 HTTP 服务与依赖注入，docker-compose 编排 Redis/Milvus/Kafka/MinIO，并提供无 API Key 的 Mock LLM 演示与单元测试。

## 可展开的面试亮点

1. **工具层为什么要与调用协议解耦**：讲清 ReAct / Function Calling / MCP 分属"模型决策层"与"工具接入层"，Broker 如何用统一签名让一份工具被三种方式复用。
2. **一次工具调用的完整管控链路**：中间件 before 钩子 → PDP 鉴权 → 参数校验 → 限流判定 →（沙箱）执行 → 中间件 after 钩子 → 审计记账，失败统一返回结构化观察。
3. **上下文工程如何降本**：大结果落 VFS、Prompt 只保留摘要 + 文件链接 + 下一步计划，配合三层记忆控制 Token。
4. **安全设计**：默认拒绝的最小权限 RBAC、NL2SQL 只读白名单与强制 LIMIT、任意代码必经 Docker 沙箱、审计入参哈希脱敏。
5. **ReAct 与 Function Calling 的工程取舍**：兼容性/可观测性 vs 格式稳定性/并行能力，为什么做成可切换双模式。
6. **工程韧性**：外部中间件（Redis/Milvus/Kafka/MinIO）不可用时的本地/内存降级策略，保证框架可离线开发与演示。
