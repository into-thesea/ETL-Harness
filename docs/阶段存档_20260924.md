## 1. 项目定位（一句话）

**通用工业级 Agent Harness Engineering 框架库**：LangGraph 负责编排，手写 Harness 管控层负责工具/权限/记忆/追踪/沙箱/质量门等企业能力。注册数据分析工具即成"数据分析 Agent"，换一套工具即换应用领域。对标 PPT 第 16 页"工业级 Agent——Harness Engineering 架构"。

- 学习模式：AI 给完整工业级代码、用户手敲；核心模块逐行教语法，非核心模块 AI 直接生成。
- 硬约束：**完整工业级实现，不简化成玩具**；工具坚持**通用**，风控专有指标（IV/WOE/KS/PSI）留作未来独立插件。

## 6. 关键架构决策（已拍板，勿再反复）

1. **执行范式**：顶层 Plan-and-Execute（Planner→Dispatch→Executor→质量门→retry/replan/human/next→Synthesize），每个子任务内部跑 ReAct（think/action/observation）。理由：ETL/数据分析宏观流程明确、需全局覆盖与可恢复；微观每步调工具需见机行事。
2. **质量门五处置**：PASS / RETRY / REPLAN / HUMAN / FAIL；Critic 仅在 use_critic 且有 acceptance_criteria 时调用，Critic 故障 fail-open 保留硬校验。
3. **工具与协议解耦**：一份工具可被 ReAct、原生 Function Calling、MCP 三协议复用，最终都归一 `broker.invoke(name, args)`。
4. **FC / MCP 口径**：ReAct 文本JSON 与 OpenAI Function Calling 同属"模型决策层"（二选一/可切换）；MCP 属"工具接入/传输层"，不冲突。当前 ReAct 可用；FC 已预留 `list_tools_openai_format()` 但 llm_client 未接线；MCP 完全未做（规划 `harness/mcp_adapter.py`）。简历文档按目标态把 FC + MCP 都写上。
5. **通用而非风控**：内置工具不写 IV/WOE/KS/PSI，未来做独立 `tools/risk_metrics.py` 或领域 Skill。
6. **code_executor 安全边界**：当前进程级回退不是安全沙箱，AST 守卫只能防误操作；生产/不可信代码必须等 #17 Docker 双层隔离。工具契约已按未来 Docker 执行器设计，到时只换执行器。
7. **绝对导入**：新模块统一 `from harness.xxx` / `from tools.xxx`。tool_broker.py 第 27-28 行用户已改为绝对导入，**保留勿动**。
