# A/B 实验分析

## 概述
规范 A/B 实验的设计前评估与结果解读。区分“统计显著”与“业务显著”，避免因统计错误做出错误决策。所有解读必须基于预设的决策规则，禁止事后调整标准。

## 强制规则

### 实验前
1. **样本量估算**：必须基于基线转化率（从历史数据获取，禁止拍脑袋）、MDE（默认相对提升 10%）、α=0.05、power=0.80 计算。如果日流量不足以在 14 天内达到所需样本量，应延长实验周期或提高 MDE，**严禁降低统计标准**。
2. **分流检查（SRM 检验）**：实验上线 24 小时内执行卡方检验，如果实验组/对照组比例偏离预期超过 1% 或卡方检验 p < 0.001，实验无效，必须排查分流问题后再继续。
3. **预注册决策规则**：实验开始前必须明确成功/失败判定标准（p 值阈值、业务 MDE、护栏指标范围）。

### 结果解读
4. **核心指标报告**：必须报告效应量（绝对提升、相对提升）、95% 置信区间、p 值，并判断是否达到业务方预设的 MDE。
5. **多重比较校正**：同时检验多个指标时，必须使用 Bonferroni 校正（α' = α / 指标数）或 FDR 校正。**严禁在多个指标中“挑选显著的那个”作为实验结论**。
6. **分群分析**：检查异质性处理效应（新老用户、设备类型、地域等），识别效果显著更强或更弱的子群体。
7. **护栏指标**：页面加载时间、错误率、投诉率、退款率必须同时监控。任何一项显著劣化（p < 0.05 且方向为负），即使核心指标显著提升，**也不得上线**。

### 禁止事项
- 禁止在样本量不足时提前查看结果（peeking）
- 禁止在 SRM 检验失败的情况下继续解读结果
- 禁止未经多重比较校正就报告多个指标的显著性
- 禁止忽略护栏指标的劣化

必须严格按照以下结构输出，不得增删字段：
```text
╔══════════════════════════════════════════════╗
║ A/B 实验分析 — {实验名称}                     ║
╠══════════════════════════════════════════════╣
║ SRM 检验     ✓ 通过（比例 49.8% : 50.2%）    ║
║ 核心指标     ✓ 提升 8.3%（95% CI: 3.2%-13.4%）║
║ p 值         ✓ 0.002（统计显著）              ║

╚══════════════════════════════════════════════╝
结论：{上线 / 不上线 / 继续观察}
理由：{一句话说明核心依据}
```

## 核心示例
**输入**：“实验组转化率5.4%，对照组5.0%，样本各1万，可以上线吗？”
**输出**：
```text
╔══════════════════════════════════════════════╗
║ A/B 实验分析 — 结账流程优化实验               ║
╠══════════════════════════════════════════════╣
║ SRM 检验     ✓ 通过（比例 50.1% : 49.9%）    ║
║ 核心指标     ✓ 提升 8.0%（95% CI: 2.1%-13.9%）║
║ p 值         ✓ 0.008（统计显著）              ║
║ 多重比较     ✓ 单指标，无需校正               ║
║ 护栏指标     ✓ 页面加载时间无显著变化          ║
╚══════════════════════════════════════════════╝
结论：上线
理由：核心指标统计显著且达到业务 MDE，护栏指标未劣化。
```
