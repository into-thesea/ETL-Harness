<a id="SRM失败排查"></a>
## SRM 失败排查

### 场景描述
实验上线 24 小时后，实验组样本量 5000，对照组样本量 8000，比例 38.5% : 61.5%，明显偏离预期的 50% : 50%。

### 错误做法
直接解读指标结果，得出“实验组效果显著”。
**问题**：SRM 失败意味着分流机制有问题，数据不可信，任何解读都是错误的。

### 正确做法
立即停止解读，执行 SRM 检验并排查分流问题。

```python
from scipy.stats import chisquare

# 观测值 vs 期望值
observed = [5000, 8000]
expected = [6500, 6500]  # 假设总样本 13000，期望各 50%
chi2, p = chisquare(observed, expected)

print(f"卡方值: {chi2:.4f}")
print(f"p值: {p:.6f}")
# p值 < 0.001 → SRM 失败
```

### 排查清单
| 排查项 | 常见原因 |
|---|---|
| 分流逻辑 | 随机化算法是否有偏差（如取模不均匀） |
| 埋点上报 | 实验组/对照组的埋点是否对称，是否有丢失 |
| 数据过滤 | 过滤条件是否对某一组产生不对称影响 |
| 实验配置 | 分流比例配置是否真的 50/50，是否被中途修改 |
| 用户身份 | 是否存在同一用户跨组（如登录/未登录切换） |
| 缓存污染 | 实验组/对照组是否存在缓存串号 |

### 正确输出
```text
╔══════════════════════════════════════════════╗
║ A/B 实验分析 — 结账流程优化实验               ║
╠══════════════════════════════════════════════╣
║ SRM 检验     ✗ 失败（比例 38.5% : 61.5%）    ║
║ 核心指标     — 暂停解读（SRM 未通过）         ║
║ p 值         — 暂停解读                       ║
║ 多重比较     — 暂停解读                       ║
║ 护栏指标     — 暂停解读                       ║
╚══════════════════════════════════════════════╝
结论：实验无效，暂不解读
理由：SRM 检验失败（p < 0.001），分流比例显著偏离预期，数据不可信。
建议动作：排查分流逻辑、埋点上报、缓存污染等，修复后重新启动实验。
```

### 自检清单
- [x] 实验上线 24 小时内执行 SRM 检验
- [x] SRM 失败时立即停止解读
- [x] 已按排查清单逐项检查
- [x] 排查结果记录到审计日志

### 注意事项
1. **SRM 是硬性门槛**：无论核心指标多么“显著”，SRM 失败时结果一律不可信。
2. **SRM 阈值可根据场景调整**：严格场景（如金融）可用 p < 0.01，一般场景 p < 0.001。
3. **SRM 修复后要重新积累样本**：不能把旧样本和修复后的样本混合分析。

<a id="多重比较校正示例"></a>
## 多重比较校正

### 场景描述
一次实验同时检验 4 个指标：点击率、转化率、客单价、留存率。原假设均为“无显著差异”，显著性水平 α = 0.05。如果直接对每个指标做检验，出现至少一次假阳性的概率为 1 - (1 - 0.05)^4 ≈ 18.5%，远高于 5%。

### Bonferroni 校正
将显著性水平除以指标数：α' = 0.05 / 4 = 0.0125。每个指标的 p 值必须 < 0.0125 才算显著。

```python
import numpy as np
from scipy import stats

# 4 个指标的 p 值
p_values = [0.002, 0.018, 0.035, 0.008]
metric_names = ["点击率", "转化率", "客单价", "留存率"]

# Bonferroni 校正
alpha = 0.05
n_metrics = len(p_values)
alpha_corrected = alpha / n_metrics
print(f"校正后显著性水平: {alpha_corrected:.4f}")

for name, p in zip(metric_names, p_values):
    significant = p < alpha_corrected
    print(f"{name}: p={p}, {'显著' if significant else '不显著'}")
```

输出：
```text
校正后显著性水平: 0.0125
点击率: p=0.002, 显著
转化率: p=0.018, 不显著
客单价: p=0.035, 不显著
留存率: p=0.008, 显著
```

### FDR 校正（Benjamini-Hochberg）
Bonferroni 校正过于保守，适合指标数较少的场景。当指标数较多（如 20+）时，建议使用 FDR 校正，控制假发现率而非假阳性率。

```python
from statsmodels.stats.multitest import multipletests

p_values = [0.002, 0.018, 0.035, 0.008]
rejected, p_corrected, _, _ = multipletests(p_values, alpha=0.05, method='fdr_bh')

for name, p, p_corr, rej in zip(metric_names, p_values, p_corrected, rejected):
    print(f"{name}: 原始 p={p}, FDR 校正后 p={p_corr:.4f}, {'显著' if rej else '不显著'}")
```

### 正确输出
```text
╔══════════════════════════════════════════════╗
║ A/B 实验分析 — 4 指标实验                     ║
╠══════════════════════════════════════════════╣
║ SRM 检验     ✓ 通过                           ║
║ 多重比较     ✓ Bonferroni 校正（α'=0.0125）   ║
║ 核心指标     ✓ 点击率 p=0.002 显著            ║
║              ✓ 留存率 p=0.008 显著            ║
║              ✗ 转化率 p=0.018 不显著          ║
║              ✗ 客单价 p=0.035 不显著          ║
║ 护栏指标     ✓ 全部正常                       ║
╚══════════════════════════════════════════════╝
结论：上线
理由：点击率、留存率经 Bonferroni 校正后显著提升，护栏指标未劣化。转化率、客单价未达显著。
```

### 自检清单
- [x] 多指标时使用 Bonferroni 或 FDR 校正
- [x] 校正后的显著性水平已明确写出
- [x] 未在多个指标中“挑选显著的那个”
- [x] 未显著指标也一并报告

### 注意事项
1. **Bonferroni 保守但简单**：适合指标数少（< 10）的场景。
2. **FDR 更灵活**：适合指标数多（>= 10）的场景。
3. **校正方法必须预注册**：不能在看到结果后才决定用哪种校正。

<a id="序贯检验"></a>
## 序贯检验（Sequential Testing）

### 场景描述
某团队希望每天查看实验结果，一旦显著就立即上线。但如果使用传统的固定样本检验，每天偷看结果会大幅提高假阳性率（peeking problem）。

### 问题说明
假设真实效果为 0，固定样本检验的假阳性率为 5%。如果每天看一次结果、看到显著就停止，连续看 14 天，假阳性率会膨胀到 30% 以上。

### 解决方案
使用序贯检验（如 O'Brien-Fleming 边界、Pocock 边界、Alpha Spending），为每次 peek 分配一部分显著性水平，使得整体假阳性率仍控制在 5% 以内。

### O'Brien-Fleming 边界示例
```python
# 假设计划 4 次中期分析 + 1 次最终分析
# O'Brien-Fleming 边界（简化示例）
import numpy as np

# 每次分析消耗的 alpha 比例
alpha_spending = [0.0001, 0.005, 0.02, 0.05, 0.05]
cumulative_alpha = np.cumsum(alpha_spending)

print("分析次数 | 单次 alpha | 累计 alpha")
for i, (a, ca) in enumerate(zip(alpha_spending, cumulative_alpha), 1):
    print(f"   {i}     |   {a:.4f}    |   {ca:.4f}")
```

输出：
```text
分析次数 | 单次 alpha | 累计 alpha
   1     |   0.0001    |   0.0001
   2     |   0.0050    |   0.0051
   3     |   0.0200    |   0.0251
   4     |   0.0500    |   0.0751
   5     |   0.0500    |   0.1251
```
（注：真实 O'Brien-Fleming 边界需要通过专业工具计算，上表仅为示意。）

### 正确输出
```text
╔══════════════════════════════════════════════╗
║ A/B 实验分析 — 序贯检验实验                   ║
╠══════════════════════════════════════════════╣
║ 检验方法     ✓ O'Brien-Fleming 序贯检验       ║
║ 计划分析次数 ✓ 4 次中期 + 1 次最终            ║
║ 当前分析     ✓ 第 2 次中期分析                ║
║ 当前边界     ✓ 单次 α = 0.0050                ║
║ 核心指标     ✗ p=0.012 > 0.0050，未达显著     ║
╚══════════════════════════════════════════════╝
结论：继续观察
理由：当前中期分析未达序贯检验边界，需继续积累样本至下一次分析。
```

### 自检清单
- [x] 实验前已确定使用序贯检验
- [x] 已明确中期分析次数和 alpha 分配
- [x] 每次分析按对应边界判定，未越界判定
- [x] 未使用固定样本检验的 p < 0.05 作为判定标准

### 注意事项
1. **序贯检验必须预注册**：中期分析次数和 alpha 分配必须在实验开始前确定。
2. **不能随意增加中期分析**：每增加一次分析都会消耗 alpha 预算。
3. **工具推荐**：可使用 `groupsequential`、`gsDesign`（R）或商业工具计算精确边界。
