<a id="警告规则处理"></a>
## 警告规则处理

### 场景描述
某日更数据表 `daily_sales` 最新分区为 2026-09-28，但今天是 2026-09-30。行数、缺失率均正常，但时效性超期。

### 错误做法
```
数据质量门校验结果：通过
```
**问题**：忽略了时效性超期，继续用旧数据出报告，可能误导决策。

### 正确做法
触发警告规则 W1，在输出中标记，并继续流程（不阻断），但在后续报告的风险提示中必须注明。

```text
数据质量门校验结果：警告
触发规则：W1 - 时效性超期
问题详情：数据最新分区为 2026-09-28，距今 2 天，超过日更数据 2 天阈值
建议动作：继续分析，但在报告风险提示中标注“数据更新至 2026-09-28，可能存在 T+2 延迟”。如果用户急需当日数据，建议联系数据工程确认 ETL 状态。
```

### 时效性阈值参考
| 数据更新频率 | 警告阈值 | 阻断阈值 |
|---|---|---|
| 日更 | 超过 2 天 | 超过 5 天 |
| 周更 | 超过 10 天 | 超过 20 天 |
| 月更 | 超过 40 天 | 超过 60 天 |
| 实时 | 超过 2 小时 | 超过 12 小时 |

### 类别值异常处理
```text
数据质量门校验结果：警告
触发规则：W2 - 类别结构漂移
问题详情：channel 字段的类别数从 12 个变为 15 个（+25%），新增类别：直播、私域、海外
建议动作：继续分析，但在报告中注明“渠道分类有新增，历史对比时需注意口径一致性”。建议人工确认新类别是否为业务扩展所致。
```

### 数值范围异常处理
```text
数据质量门校验结果：警告
触发规则：W3 - 数值范围异常
问题详情：age 字段存在 47 个超出 [0, 150] 的值（含负数 3 个，超过 150 的 44 个）
建议动作：继续分析，交由 outliers Skill 在清洗阶段处理，清洗后需重新检查是否仍有异常。
```

### 自检清单
- [x] 时效性超期已标记并在报告风险提示中注明
- [x] 类别结构漂移已标记并说明口径影响
- [x] 数值范围异常已标记并移交清洗阶段
- [x] 警告不阻断流程，但必须传递到最终报告

<a id="质量门升级流程"></a>
## 质量门升级流程

### 场景描述
数据质量门触发了红线规则，但用户表示“上游已确认，这次数据虽然缺失率高但可以用”。

### 错误做法
直接绕过质量门，继续分析。
**问题**：绕过质量门会丧失审计痕迹，且上游“确认”可能没有书面依据。

### 正确做法
走人工审批流程，记录豁免理由和审批人，并将豁免信息写入 VFS 审计日志。

### 审批流程
```
1. Agent 检测到红线触发 → 暂停任务
2. 向用户展示问题详情 → 询问是否申请豁免
3. 用户申请豁免 → 提示需要填写：
   - 豁免理由
   - 上游确认人
   - 豁免有效范围（仅本次 / 长期）
4. 生成豁免请求 → 发送至审批流（企业微信/钉钉/邮件）
5. 审批通过 → 记录审计日志 → 继续分析，报告中必须附带豁免声明
6. 审批拒绝 → 保持阻断状态，提示用户修复数据
```

### 豁免审计日志格式
```json
{
  "timestamp": "2026-09-30T10:15:00+08:00",
  "skill": "data-quality-gate",
  "triggered_rule": "R1",
  "field": "customer_id",
  "issue": "缺失率 35%",
  "exemption_reason": "上游 ETL 已知问题，客户 ID 缺失不影响本次渠道分析",
  "approver": "data_engineer_zhang",
  "approval_id": "EX-20260930-001",
  "scope": "single_task",
  "task_id": "task_20260930_channel_analysis"
}
```

### 报告中的豁免声明
```text
━━━ 数据质量豁免声明 ━━━
本次分析存在 1 处数据质量红线豁免：
- 规则：R1 关键字段缺失率超标
- 字段：customer_id（缺失率 35%）
- 豁免理由：上游 ETL 已知问题，客户 ID 缺失不影响本次渠道分析
- 审批编号：EX-20260930-001
```

### 自检清单
- [x] 红线触发后暂停任务，未直接绕过
- [x] 豁免申请包含理由、确认人、范围
- [x] 审批通过后记录审计日志
- [x] 报告中附带豁免声明

### 注意事项
1. **豁免不是常态**：同一规则在同一数据源上频繁豁免，说明上游数据质量问题需要根治，应反馈给数据工程团队。
2. **豁免范围要明确**：单次任务豁免不能自动扩展为长期豁免。
3. **审计日志不可篡改**：所有豁免记录必须持久化到 VFS 或企业审计平台。

<a id="GreatExpectations集成"></a>
## Great Expectations 集成

### 场景描述
企业已有 Great Expectations（GE）数据质量套件，希望与本 Skill 配合使用，避免重复造轮子。

### 集成策略
本 Skill 定义**红线规则和阻断逻辑**，GE 负责**数据质量校验的执行引擎**。两者通过以下方式配合：

1. **规则映射**：将本 Skill 的 R1-R4 红线规则映射为 GE 的 Expectation。
2. **执行时机**：在数据获取后立即触发 GE 校验，结果传递给本 Skill。
3. **结果判定**：本 Skill 根据 GE 的校验结果决定是否阻断。
4. **审计记录**：GE 的校验结果作为豁免审计日志的附件。

### GE Expectation 映射参考

| 本 Skill 规则 | GE Expectation |
|---|---|
| R1 关键字段缺失率 > 30% | `expect_column_values_to_not_be_null` + 阈值参数 |
| R2 行数波动 > ±20% | `expect_table_row_count_to_be_between` + 动态基线 |
| R3 主键重复 | `expect_column_values_to_be_unique` |
| R4 关键字段全空 | `expect_column_values_to_not_be_null`（阈值 100%） |
| W1 时效性超期 | `expect_column_max_to_be_between` + 动态日期 |
| W2 类别结构漂移 | `expect_column_values_to_be_in_set` + 集合对比 |
| W3 数值范围异常 | `expect_column_values_to_be_between` |

### 集成代码示例
```python
import great_expectations as ge
from harness.skills.data_quality_gate import check_quality_gate

# 用 GE 执行校验
df = ge.read_csv("/workspace/raw/sales.csv")
ge_result = df.expect_column_values_to_not_be_null("customer_id")

# 传递给本 Skill 判定
skill_result = check_quality_gate(
    ge_result=ge_result,
    rule="R1",
    threshold=0.3,
    field="customer_id"
)

if skill_result["blocked"]:
    raise DataQualityBlocked(skill_result["message"])
```

### 自检清单
- [x] 红线规则已映射到 GE Expectation
- [x] GE 校验结果作为本 Skill 的输入
- [x] 豁免审计日志附件包含 GE 校验原始结果
- [x] 未重复实现 GE 已有的校验逻辑

### 注意事项
1. **不要在本 Skill 中重写 GE 的校验逻辑**：本 Skill 只负责“判定和阻断”，校验执行交给 GE。
2. **GE 的 validation result 要完整保留**：便于事后审计和问题复现。
3. **自定义 Expectation 的优先级**：企业特有的校验规则（如“某字段必须符合业务枚举值”）应写成自定义 Expectation，而非硬编码在 Skill 中。

## 与中间件配合

本 Skill 的方法论与框架的 `QUALITY_DATA_CHECK_ENABLED` 中间件配合使用：
- 中间件执行硬性检查（缺失率、行数波动、主键重复），并在触发时阻断执行。
- 本 Skill 提供检查后的解释、建议动作和豁免流程。
- 中间件记录的检查结果作为本 Skill 判定和审计的依据。

如果数据质量门触发了阻断，任务暂停，等待用户修复数据或申请豁免后方可继续。
