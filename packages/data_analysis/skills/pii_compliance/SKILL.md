# PII 合规

## 概述
规范数据分析过程中的个人可识别信息（PII）处理。本 Skill 优先级最高，触发时自动覆盖其他分析类 Skill 的行为。合规是不可协商的底线，任何分析效率的优化都不得以牺牲合规为代价。

## PII 识别清单
在分析任何数据之前，扫描以下字段类型。如果发现，标记为 PII：

| 类别 | 示例字段名 | 识别方式 |
|---|---|---|
| 身份证 | id_card, sfz, 身份证 | 18 位数字+校验位 |
| 手机号 | phone, mobile, 手机 | 11 位数字，1 开头 |
| 银行卡 | bank_card, 银行卡 | 16-19 位数字，Luhn 校验 |
| 姓名 | name, 姓名, customer_name | 中文姓名 2-4 字 |
| 地址 | address, 地址 | 包含省/市/区关键词 |
| 邮箱 | email, 邮箱 | 包含 @ 符号 |

框架内置的中文 PII 识别中间件会自动执行上述识别，本 Skill 负责识别后的处理决策。

## 强制处理策略
1. **SQL 层面脱敏（优先）**：在生成 SQL 时，对 PII 字段使用哈希或掩码替代明文字段：
   - 身份证：`CONCAT(LEFT(id_card, 6), '****', RIGHT(id_card, 4))`
   - 手机号：`CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4))`
   - 姓名：`CONCAT(LEFT(name, 1), '**')`
2. **聚合抑制**：分组结果每组记录数 < 5 条时，对该组指标值做抑制处理（显示为“<5”或置空），防止通过小样本反推个人身份。
3. **报告输出审查**：禁止展示任何未脱敏的 PII 字段；禁止在图表标题、轴标签、数据标签中出现完整身份证号、手机号；禁止在结论文字中引用可识别个人的具体信息。

## 强制红线
- 禁止在 VFS 中明文存储 PII 字段
- 禁止将 PII 字段作为分析的分组维度
- 禁止在未脱敏的情况下执行 `SELECT *`
- 如果用户要求查询特定个人的信息，必须走人工审批流程

## 输出契约
分析报告末尾必须自动附加以下合规声明，不得增删字段：
```text
━━━ 合规声明 ━━━
本报告已执行 PII 脱敏处理。
涉及敏感字段：{字段列表}
脱敏策略：{哈希/掩码/抑制}
审批编号：{如有}
```

## 核心示例
**输入**：“分析用户手机号段分布。”
**输出**：
```text
━━━ 合规声明 ━━━
本报告已执行 PII 脱敏处理。
涉及敏感字段：phone
脱敏策略：掩码，SQL 中已替换为 CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4))
审批编号：无（常规脱敏，无需审批）
注：分组结果每组均 > 5 条，无需聚合抑制。
```
