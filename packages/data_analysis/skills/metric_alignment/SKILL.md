# 口径统一 SOP（结合长期记忆）

同一业务术语在不同团队常含义不同；同名不同义、同义不同名是分析错误的主要来源。

1. **遇到业务术语先检索，不臆测**：在写 SQL 前，先从长期记忆 / 数据字典检索该
   指标的标准定义、来源表、字段、过滤条件、统计粒度与时间口径。
2. **明确口径五要素**：定义公式、数据源（表/字段）、统计维度与粒度、时间范围
   （自然日/业务日、时区）、包含与排除规则（是否含退款、取消、内部单）。
3. **歧义处理**：检索不到或存在多个冲突定义时，列出差异并显式向人确认，
   不自行选择一个默认值后当作结论。
4. **转标准逻辑**：确认后把术语翻译成可复用的 SQL / 计算逻辑，避免在多处各写一遍。
5. **沉淀**：本次新确认或纠正的口径，回写到长期记忆（术语→标准定义/SQL），
   后续任务直接复用，逐步消除黑话。
6. 报告中关键指标须注明口径，保证"同一指标在图表、正文、SQL 中一致"。
