# 归因分析

## 概述
规范指标波动的归因分析流程。当用户询问“为什么某指标变化了”时，按本 SOP 执行，避免臆测和逻辑谬误。归因分析必须建立在数据基础上，结论必须可溯源。

## 强制规则
1. **必须确认现象**：明确指标名、对比时间段（同比/环比/自定义）、变化幅度（绝对值和百分比）三要素。缺失时主动询问，禁止跳过直接下钻。
2. **必须逐维度下钻**：按时间 → 地域 → 渠道/产品 → 用户的优先级依次拆解，每个维度计算贡献度 = （该维度的变化量）/（总变化量）× 100%。
3. **收入类指标必须做量价分解**：量效应 =（本期量-基期量）×基期价；价效应 =（本期价-基期价）×本期量。
4. **必须检查三大逻辑陷阱**：
   - **辛普森悖论**：整体趋势与各分组趋势方向相反时，以分组结论为准，并在输出中明确提示。
   - **幸存者偏差**：确认数据是否只包含“存活下来”的样本。
   - **因果方向**：相关性不等于因果性，除非有明确业务机制支撑。
5. **结论必须可溯源**：每个归因结论必须附带 SQL 文件路径或 VFS 文件路径。
6. **禁止模糊措辞**：禁止使用“可能”“大概”“也许”等词，除非明确标注为“假设”并说明验证方法。

## 输出契约
必须严格按照以下结构输出，不得增删字段：
```text
归因结论：{指标} 在 {时间段} 变化 {幅度}
主要驱动维度：{维度名}，贡献度 {X}%
次要驱动维度：{维度名}，贡献度 {Y}%
数据支撑：{SQL文件路径或VFS文件路径}
风险提示：{如存在辛普森悖论风险/样本偏差风险，在此说明}
```

## 核心示例
**输入**：“为什么华东区上周GMV下降了10%？”
**输出**：
```text
归因结论：GMV在2026-09-14至2026-09-20期间下降10%
主要驱动维度：华东区，贡献度 85%
次要驱动维度：移动端渠道，贡献度 15%
数据支撑：/workspace/reports/attribution_20260921.sql
风险提示：华东区整体呈下降趋势，但下沉城市呈现逆势增长，需警惕辛普森悖论风险。
```
